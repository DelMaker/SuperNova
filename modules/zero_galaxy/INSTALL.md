# Нулевая галактика 0.8.0: установка

Модуль готов для тестовой установки администрацией. Он не изменяет файлы ядра; совместимость с другими сборками SuperNova и сочетаниями модулей нужно проверить на копии игры.

## Проверенная среда

- SuperNova 46d0, штатный обработчик флотов и шаблоны OpenGame.
- PHP 7.4.33, 64 bit; `mysqli`, JSON и функции `mbstring` либо их совместимые реализации в ядре.
- MariaDB 10.11.19, InnoDB. Другие версии БД и PHP 8 не проверены.
- Современный браузер с JavaScript и BigInt для выбора атакующего флота.

Должны работать обычные полёты и подписанные служебные HTTP-запросы обработчика флотов. В штатной схеме связь `fleets.fleet_end_planet_id` с планетой должна иметь `ON DELETE SET NULL`. Пользователю БД нужны права чтения и изменения игровых записей и создания таблиц модуля. Серверный `secretword` должен содержать не менее 16 символов; в пакет чужой ключ не входит.

«Капитаны» необязательны. Для отправки капитана и начисления опыта нужен уже установленный совместимый модуль `unit_captain`. Его исходники в архив не включены.

## Состав и баланс

Каталог `modules/zero_galaxy/` содержит код, изображения, переводы, штатные обёртки интерфейса, проверки и настройки:

- `defaults.php` — полный текущий настроенный баланс: семь категорий, стоимости, технологии, фазы, ресурсы, частоты и лимиты.
- `config.php.example` — пример частичных переопределений. Для своих изменений скопируйте его в `config.php` в том же каталоге.
- `SETTINGS.md` — комментарии к параметрам.

Если `config.php` отсутствует, используются значения `defaults.php`. Не копируйте сюда основной конфиг игры, пароли БД или настройки Docker. При обновлении существующей установки сохраните её собственный `config.php` отдельно.

Баланс рассчитан под обсуждавшиеся крупные значения очков. Его пригодность для экономики другого сервера проверяется отдельно. Новые настройки гарнизона, ресурсов, лимита и фаз действуют на следующие появления. Технологии статичны и общие для вида разлома: изменения `tech` применяются к существующим планетам на очередном тике без перезапуска. На каждый вид создаётся один NPC. Новый вид требует полной записи настроек; `categories.<ключ> => null` удаляет вид вместе с его разломами, планетами, обломками и NPC, сохраняя полёты.

На разломы разрешены только одиночные атаки. Кнопки создания и приглашения САБа и нулевые группы в форме выбора цели недоступны; групповые рейсы возвращаются по отдельности без боя. Штатные САБы обычных галактик работают без изменений.

Имена планет разломов и NPC сохраняются в БД на языке сервера (`game_default_language`) и попадают в отчёты в этом виде. Обзор показывает имена на языке игрока.

В `docs/` находятся описание механик для администрации, анонс и правила для игроков, а также исходный файл лицензии SuperNova. Дампов БД, игроков, локальных секретов, Docker и копии «Капитанов» нет.

## Установка на копию игры

1. Сохраните резервную копию БД и существующего модуля, если он уже установлен.
2. Из распакованного пакета перенесите только каталог `modules/zero_galaxy/` в одноимённое место игры. Имя каталога менять нельзя. Документация не заменяет файлы движка.
3. При необходимости подготовьте `config.php` до первого входа. Чтобы сначала проверить совместимость без новых разломов, задайте `$zero_galaxy_config = ['target_active_per_system' => 0];` в PHP-файле. NPC настроенных видов будут созданы. Рабочий ориентир плотности — `2`.
4. Войдите в игру. Штатный загрузчик подключит модуль автоматически: отдельной регистрации нет. Первый авторизованный запрос создаст три таблицы с префиксом игры: `zero_galaxy_state`, `zero_galaxy_rifts`, `zero_galaxy_npcs`. При включённой генерации начнётся появление разломов.
5. Откройте «Нулевая галактика» либо введите галактику `0` в обычном обзоре Вселенной. Атака из обзора и отчёта шпионажа открывает обычный `fleet.php`. Через «Флот на орбите» также можно выбрать корабли и указать галактику `0` вручную. При агрессивном кэшировании обновите OPcache, шаблоны и браузер штатным способом своего сервера.

Перед доступом игроков проверьте появление и закрытие планет, шпионаж, атаку из отчёта, выбор флота с лимитом, выбор шпионажа для планеты и переработки для обломков, бой и возврат. Проверьте отсутствие создания и присоединения к САБам разломов. Проверьте отправку атаки из «Флот на орбите» на пустые координаты, отказ при превышении лимита существующего разлома, отказ переработчикам без планеты или обломков и сбор существующего поля обломков, удаление цели с летящими флотами и сохранность уже собранного груза. Обычные галактики должны продолжать работать.

## Обновление с версий до 0.8.0

Модуль 0.8.0 не переносит данные старых версий: перенос выполняется отдельно, до замены кода. Новая установка этих шагов не требует.

- **Владельцы разломов.** Каждый разлом должен иметь `npc_owner_id`, равный `owner_id` NPC своей категории в `zero_galaxy_npcs`, а реестр NPC — ключи `category_key`. Единый владелец `zero_galaxy_state.npc_owner_id` и NPC отдельных разломов больше не переносятся: разлом другого владельца останавливает пересчёт мира без изменений. Столбец `zero_galaxy_state.npc_owner_id` модулем не используется и может остаться.
- **Профили.** Разлом без полного профиля версии 1 (категория с ключом, названием и цветом, `fleet_limit`, `fleet`, `defence`, `resources`) удаляется на очередном тике вместе со своей планетой.
- **Схема.** Таблицы создаются только целиком; столбцы старых версий не добавляются. Нужна схема 0.7.x: `zero_galaxy_npcs.category_key`, `zero_galaxy_rifts.planet_id` и `npc_owner_id`, `zero_galaxy_state.stats_hidden_ids`.
- **Настройки.** Ключи `acs_enabled`, `energy_seconds`, `active_seconds`, `unstable_seconds`, `closed_seconds` удалены. Если они остались в `config.php`, конфигурация считается ошибочной и обновление мира останавливается: удалите их.
- **Интерфейс.** Формы флота, открытые до обновления, придётся открыть заново: изменился формат подписи. Адрес `index.php?page=zero_galaxy_attack` удалён. Быстрые шпионаж и переработка идут через штатный `flotenajax.php`.

## Проверки и ограничения версии

Устройство модуля описано в `ARCHITECTURE.md`. Все PHP-проверки запускаются одной командой внутри веб-контейнера: `php modules/zero_galaxy/tests/run.php`; ключ `--no-db` пропускает проверки с базой данных. Проверки БД создают таблицы со случайным префиксом `zg_` и удаляют их. JavaScript-проверки запускаются через Node: `node modules/zero_galaxy/tests/<имя>.js`. Это не подтверждение совместимости с любым сервером и не нагрузочный тест.

- Луны, специальные награды и личные бонусы к боевому лимиту отключены намеренно; САБы на разломы недоступны.
- Повторная отправка корректного POST создаёт новый рейс при наличии кораблей, топлива и свободных слотов. Это допустимая игровая механика; каждый рейс независимо проходит проверки цели и лимита.
- При дробных курсах ресурсов клиентская оценка стоимости флота может отличаться от серверной из-за округления. Решение принимает серверная проверка.
- Пользовательские темы, другие обработчики флотов и модули захвата требуют проверки совместимости. Массовые одновременные рейсы не проходили нагрузочное тестирование.

## Обновление и отключение

Не заменяйте обработчик флотов и не удаляйте модуль, пока остаются рейсы в Нулевую галактику или обратно. Отказ в новых отправках при конфликте обработчиков не защищает автоматически уже летящие флоты.

Для остановки задайте `target_active_per_system => 0`, дождитесь исчезновения разломов и завершения всех направленных и возвращающихся рейсов. Только после этого отключайте или заменяйте код, сохранив резервную копию. Автоматического удаления NPC, таблиц и настроек модуля из игры нет.

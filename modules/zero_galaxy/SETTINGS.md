# Настройки Нулевой галактики

`defaults.php` содержит полный баланс. Для своей игры скопируйте `config.php.example` в `config.php` рядом с ним и изменяйте массив `$zero_galaxy_config`. `Settings::load()` заново читает defaults при каждом вызове; конфигурацию модуля загружает движок на каждом запросе. Перезапуск приложения не нужен. Если на сервере отключена проверка изменений файлов OPcache, применяются правила обновления PHP этого сервера.

Переопределения частичные: можно изменить только `categories.great.limit`, только среднее время одной фазы или один вес юнита. Остальные поля и категории сохраняются. Неизвестные ключи и категории, неверные типы, отрицательные веса, бесконечности и `NaN` вызывают `InvalidArgumentException`. При ошибке конфигурации вызывающий код должен продолжить очистку истёкших разломов с выключенной генерацией.

Уже созданные разломы сохраняют записанные категорию, профиль и сроки; изменение баланса действует на новые. Новый лимит не удаляет существующие разломы. Снижение лимита ниже текущего количества приостанавливает новые появления этой категории, пока число занятых мест не уменьшится.

Служебные NPC не входят в рейтинг игроков: модуль синхронизирует собственные ID со штатным `stats_hide_player_list`. Ручные исключения администрации сохраняются; после удаления NPC его автоматическое исключение очищается.

## Общие параметры

- `target_active_per_system`: целевая средняя плотность доступных планет, включая активную и нестабильную фазы. Это статистическая цель, а не точное число в каждой системе. `0` выключает генерацию новых разломов.
- `tick_seconds`: минимальный интервал обслуживания мира, по умолчанию 15 секунд.
- `generation_seconds`: интервал расчёта новых появлений, по умолчанию 300 секунд.
- `refresh_seconds`: интервал обновления интерфейса, по умолчанию 30 секунд; значения ниже 2 нормализуются до 2.
- `fleet_limit_multiplier`: базовый множитель допустимой стоимости флота атакующего относительно **начальной** стоимости флота и обороны NPC; по умолчанию `1.25`. Лимит округляется вниз, фиксируется при создании разлома и не уменьшается после потерь гарнизона. Он отображается в обзоре и штатной форме комплектации флота, проверяется при отправке и прибытии атаки. Равная лимиту стоимость допустима, отказ происходит только при превышении. Личные бонусы к допуску пока не включены.
- `acs_enabled`: САБы против разломов, по умолчанию `true`. Используйте только PHP-значения `true` / `false`, без кавычек. Каждый участник получает обычный лимит разлома; несколько его флотов в одном САБе делят этот лимит. При `false` исчезают кнопки создания/приглашения САБа у атак на разломы и такие группы в форме выбора цели; создание и присоединение запрещены на сервере. Уже летящие САБы возвращаются без боя при прибытии. Обычные галактики сохраняют штатные САБы. Настройка применяется на следующем запросе, в том числе после перезапуска сервера; при OPcache без проверки времени файлов нужен его штатный сброс или перезапуск PHP.

Положительные интервалы секунд ограничены годом; множитель допускает значения от 0.01 до 100.

## Семь категорий

Порядок ключей фиксирован: `tiny`, `small`, `medium`, `large`, `huge`, `colossal`, `great`. Состав категорий нельзя расширить одним конфигом: новый ключ требует поддержки хранения и интерфейса.

- `tiny`: Крошечный, салатовый `#ADFF2F`; вес 30, без лимита; средняя стоимость гарнизона 80 000 000, средняя технология 8.
- `small`: Малый, зелёный `#32CD32`; вес 25, без лимита; стоимость 978 676 804, технология 12.
- `medium`: Средний, белый `#FFFFFF`; вес 20, без лимита; стоимость 11 972 603 592, технология 18.
- `large`: Большой, жёлтый `#FFD700`; вес 15, без лимита; стоимость 146 466 367 788, технология 24.
- `huge`: Огромный, красный `#FF4040`; вес 7, лимит 100; стоимость 1 791 790 459 627, технология 30.
- `colossal`: Колоссальный, фиолетовый `#BF70FF`; вес 2.5, лимит 10; стоимость 21 919 797 013 468, технология 33.
- `great`: Великий, тёмно-фиолетовый `#7B2CBF`; вес 0.5, лимит 2; стоимость 268 154 961 162 000, технология 35.

Средние стоимости округлены до целого из геометрической прогрессии с коэффициентом примерно 12.23346. Средний гарнизон great равен 50% опорной стоимости флота test_top 536 309 922 324 000. Это стартовые значения баланса.

`name` — название, `color` — цвет строго в виде `#RRGGBB`. `weight` — относительный вес выбора среди доступных категорий: сумма не обязана быть 100; `0` исключает категорию из новых появлений. Вероятности меняются, когда категории достигают лимита.

`limit` — общий лимит категории **по всей Нулевой галактике**, а не по системе. `-1` означает без лимита, `0` запрещает новые появления. Место резервируется при рождении разлома и остаётся занятым во всех четырёх неистёкших фазах, включая энергию и закрытие; освобождается после `disappears_at`. Даже закрытый разлом без планеты занимает место. Реальное соблюдение лимита и выбор категории выполняет Storage под блокировкой; Settings проверяет только баланс.

## Гарнизон и ресурсы

`garrison_points` содержит `mean` — среднюю общую стоимость флота **и** обороны в металлическом эквиваленте, и `spread_percent` — симметричный процент разброса. При `mean=80000000`, `spread_percent=20` диапазон равен 64–96 млн. Базовый лимит атакующего при множителе 1.25 равен 80–120 млн; 100 млн — среднее, а не верхняя граница. Дробные границы округляются наружу до целых, нижняя стоимость не меньше 1. Среднее — целое от 1 до 4 000 000 000 000 000, разброс — от 0 до 100%.

В форме атаки видны лимит цели, стоимость выбранных кораблей и остаток допуска либо превышение. Стоимость всего выбранного флота суммируется и округляется вниз один раз. Если на координатах к прибытию появился другой гарнизон, действует лимит нового профиля; при отсутствии доступной цели или превышении флот возвращается без боя. Старые пустые разломы без профиля гарнизона атаковать нельзя.

`fleet_share_percent` задаёт долю бюджета флота; остальное получает оборона. Значение по умолчанию 60 означает 60% флоту и 40% обороне. При переводе бюджета в целые количества юнитов фактическая стоимость может быть немного меньше запланированной.

`fleet_weights` и `defence_weights` задают относительные доли стоимости конкретных типов юнитов; ключи — штатные `unit_snid`, а не ID записей в таблице `unit`. Например, `204` — лёгкий истребитель, `401` — ракетная установка. При генерации каждый вес независимо умножается на случайное число от 0.5 до 1.5: одинаковая категория не означает одинаковый состав. Значение `0` отключает тип, но в каждом наборе должен остаться положительный вес. Частичное переопределение одного ID сохраняет остальные; чтобы оставить единственный тип, остальные веса надо явно обнулить. Дополнительные ID можно добавить. Модуль проверяет их существование, тип и стоимость по данным ядра.

`resource_percent` — доля **фактической начальной стоимости только флота**, по умолчанию 75%. `resource_spread_percent=20` даёт дополнительный множитель от 0.8 до 1.2: ресурсы составят 60–90% стоимости флота. Оборона не входит в эту базу; стоимость всего гарнизона применять здесь нельзя. Допустимый ресурсный процент 0–10000, разброс 0–100%.

Ресурсы распределяются игровым профилем в постоянных долях металлического эквивалента M:C:D = 60:25:15. Это не соотношение сырых количеств: стоимость каждой доли делится на соответствующий курс ядра. Сами курсы берутся тем же способом, что и в штатной статистике/`eco_get_total_cost`; из-за округления итог может быть немного ниже бюджета. После рождения ресурсы не пересчитываются из оставшегося флота.

Победный рейд вывозит до половины оставшихся ресурсов по штатным правилам вместимости. Новая конфигурация и обслуживание фаз не пополняют добычу или уничтоженные корабли; частичное восстановление обороны выполняет штатный бой. Луны и специальные награды отключены, обломки доступны для сбора до перехода в закрытую фазу, затем исчезают вместе с планетой. Переработчики используют штатный сбор без боевого лимита; закрытие не уничтожает уже собранный груз возвращающихся флотов.

## Технологии

`tech` — карта `ID => ['mean' => целое, 'spread' => целое]`. Здесь `spread` — **абсолютные уровни**, не проценты. Например, 35 ± 2 даёт целые уровни 33–37; нижняя граница ограничивается нулём. Верхняя граница не выше 1000. Для отключения технологии укажите `mean=0, spread=0`.

По умолчанию заданы только четыре технологии: `106` — шпионаж, `109` — оружие, `110` — щиты, `111` — броня. В каждой категории среднее соответствует списку выше, разброс равен 2. Для неподвижных NPC двигатели не требуются. При необходимости можно также настроить штатные `108` (компьютер), `113` (энергия), `114` (гиперпространство), `115`, `117`, `118` (двигатели). Другие ID отвергаются. При добавлении необязательного ID пропущенные `mean`/`spread` равны 0.

## Время фаз

`phases_hours` содержит четыре ключа `energy`, `active`, `unstable`, `closed`; каждый имеет `mean` в **часах** и `spread_percent`. Это длительности отдельных последовательных фаз, не абсолютные сроки.

Для tiny/small/medium/large средние равны 0.75 / 10 / 2.5 / 1.5 часа. Для huge они умножаются на 1.2, для colossal — на 1.5, для great — на 2. Во всех случаях разброс по умолчанию ±20%. Таким образом, у tiny диапазоны секунд равны [2160,3240], [28800,43200], [7200,10800], [4320,6480].

`Settings::categoryPhaseRanges($category)` возвращает `energy_seconds`, `active_seconds`, `unstable_seconds`, `closed_seconds` с включительными целыми границами. Минимальная длительность — 1 секунда, максимальная граница каждой фазы — год. Сборка нового жизненного цикла: `Lifecycle::create($now, array_replace($settings, Settings::categoryPhaseRanges($category)))`. Созданные абсолютные сроки хранятся в записи разлома и не меняются при следующей правке конфига.

Любая победа атакующего немедленно переводит доступную планету в нестабильность. Сохранённые `closes_at` и `disappears_at` остаются прежними: победа не сокращает и не продлевает жизнь цели. Поражение и ничья сами по себе фазу не меняют.

Глобальные `energy_seconds`, `active_seconds`, `unstable_seconds`, `closed_seconds` **устарели**, но сохраняются и проверяются для старого API Lifecycle и тестов. Они заменяются только целым массивом `[min,max]`, единица — секунды. Это отдельный legacy fallback: новые категории используют `phases_hours`, глобальные секунды их не переопределяют. Для ускорения новых разломов меняйте часы нужных категорий; уже существующие сроки это не сдвинет.

Класс Settings нормализует данные и строит границы; случайные значения, сохранение профиля, лимиты появления, фактическую стоимость и ограничения отправки флота реализуют остальные классы модуля.
